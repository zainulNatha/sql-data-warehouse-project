# 📦 Product Report

## Overview

The Product Report provides a consolidated product-level view built from the **Gold Layer** of the data warehouse.

The report combines product information with sales transaction data to analyse product performance, sales activity, customer reach, and revenue generation.

The final dataset produces **one row per product** and is stored as the following SQL view:

```sql
gold.report_products
```

---

## 🎯 Report Objectives

The report was created to:

* Combine sales transactions with product information.
* Aggregate transactional data to the product level.
* Calculate total orders, sales, quantity sold, and unique customers.
* Identify each product's latest sale date.
* Calculate product lifespan based on first and latest sales.
* Measure product recency.
* Calculate average selling price.
* Calculate average order revenue.
* Calculate average monthly revenue.
* Segment products based on their overall sales performance.

---

## 📊 Key Product Metrics

| Metric                | Description                                                  |
| --------------------- | ------------------------------------------------------------ |
| `total_orders`        | Number of unique orders containing the product               |
| `total_sales`         | Total sales revenue generated by the product                 |
| `total_quantity`      | Total quantity of the product sold                           |
| `total_customers`     | Number of unique customers who purchased the product         |
| `last_sale_date`      | Most recent date the product was sold                        |
| `lifespan`            | Number of months between the product's first and latest sale |
| `recency_in_months`   | Number of months since the product's latest sale             |
| `avg_selling_price`   | Average selling price per unit                               |
| `avg_order_revenue`   | Average revenue generated per order                          |
| `avg_monthly_revenue` | Average revenue generated per month                          |

---

## 🏷️ Product Segmentation

Products are grouped into performance segments based on total sales revenue.

| Segment            | Business Rule                         |
| ------------------ | ------------------------------------- |
| **High-Performer** | Total sales > 50,000                  |
| **Mid-Range**      | Total sales between 10,000 and 50,000 |
| **Low-Performer**  | Total sales < 10,000                  |

This segmentation helps identify which products generate the greatest amount of revenue and which products may require further analysis.

## 🛠️ SQL Techniques Used

### Common Table Expressions (CTEs)

CTEs are used to divide the report into logical processing stages.

```sql
WITH base_query AS (...),
product_aggregations AS (...)
```

The `base_query` retrieves the required sales and product information.

The `product_aggregations` CTE then summarises the transactional data at product level.

---

### LEFT JOIN

```sql
LEFT JOIN gold.dim_products p
    ON f.product_key = p.product_key
```

Used to combine sales transactions from the fact table with product information from the product dimension.

---

### COUNT DISTINCT

```sql
COUNT(DISTINCT order_number)
COUNT(DISTINCT customer_key)
```

Used to calculate:

* Unique orders
* Unique customers

---

### SUM

```sql
SUM(sales_amount)
SUM(quantity)
```

Used to calculate total product revenue and total quantity sold.

---

### MIN and MAX

```sql
MIN(order_date)
MAX(order_date)
```

Used to identify the first and latest product sales.

These dates are then used to calculate product lifespan.

---

### DATEDIFF & GETDATE

```sql
DATEDIFF(MONTH, MIN(order_date), MAX(order_date))
```

Used to calculate product lifespan.

`DATEDIFF` and `GETDATE()` are also used to calculate the number of months since the product's latest sale.

---

### AVG, CAST, NULLIF & ROUND

```sql
ROUND(
    AVG(
        CAST(sales_amount AS FLOAT) /
        NULLIF(quantity, 0)
    ),
    1
)
```

These functions are combined to calculate the average selling price.

* `CAST` converts the sales value to a decimal-compatible data type.
* `NULLIF` prevents division by zero.
* `AVG` calculates the average unit selling price.
* `ROUND` formats the result to one decimal place.

---

### GROUP BY

```sql
GROUP BY
    product_key,
    product_name,
    category,
    subcategory,
    cost
```

Used to aggregate multiple sales transactions into a single record for each product.

---

### CASE Statements

`CASE` expressions are used to apply business rules and calculate product segments.

Example:

```sql
CASE
    WHEN total_sales > 50000 THEN 'High-Performer'
    WHEN total_sales >= 10000 THEN 'Mid-Range'
    ELSE 'Low-Performer'
END
```

`CASE` is also used to safely calculate average order revenue and average monthly revenue where a denominator could be zero.

---

### CREATE VIEW

```sql
CREATE VIEW gold.report_products AS
```

The completed product report is stored as a reusable SQL view within the Gold Layer, making it available for future reporting, analysis, and dashboard development.
